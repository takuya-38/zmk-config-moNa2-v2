# 0001: レイヤータップは押している時間だけで長押しを判定する

- 日付: 2026-09-26
- 状態: 採用

## 背景

MAC レイヤーでは S と K をレイヤータップにしている。
押してすぐ離すと文字、押し続けるとレイヤーに切り替わる。

| キー | 押してすぐ離す | 押し続ける |
| --- | --- | --- |
| S | s | レイヤー 2（数字・記号） |
| K | k | レイヤー 7（SCRL_M） |

配布時の設定（`balanced`）のまま日本語をローマ字で打つと、`su` や `ku` の S・K が長押し扱いになり、文字が消えてレイヤー側のキーが出ることがあった。

原因は、ローマ字では子音の直後に母音が来ることにある。
子音から母音へは 1 文字の中の 2 打なので指の動きが速く、母音のキーが子音のキーを押している間に収まりやすい。

```
S  ■■■■■■□
U    ■■□        ← U が S の中に収まる
```

`balanced` は、押している間に別のキーを押して離すと長押しと判定する。
そのため、この形になると S はレイヤー切り替えになる。

## 決定

レイヤータップ（`&lt`）を次の設定にする。

```
&lt {
    quick-tap-ms = <200>;
    flavor = "tap-preferred";
    tapping-term-ms = <300>;
    require-prior-idle-ms = <150>;
};
```

| 設定 | 意味 |
| --- | --- |
| `quick-tap-ms = <200>` | 配布時のまま。離してから 0.2 秒以内に押し直すと必ず文字になり、連打できる |
| `flavor = "tap-preferred"` | 押している時間だけで判定する。押している間に別のキーを押しても判定は変わらない |
| `tapping-term-ms = <300>` | 0.3 秒押し続けたら長押し（レイヤー切り替え）になる |
| `require-prior-idle-ms = <150>` | 直前の文字入力から 0.15 秒以内に押したら、長さに関係なく必ず文字になる |

長押しの境目を 300ms にしたのは、200ms のとき、打ち始めや次の文字を迷ったときに S を 0.2 秒以上押してしまい、文字が消えることがあったため。

ModTap（`&mt`：A・Z・Space など）は配布時の設定（`balanced`、200ms）のままにする。

## 他の案を採らなかった理由

| 案 | 採らなかった理由 |
| --- | --- |
| ModTap も `tap-preferred` にする | 0.3 秒待たないと修飾キーにならず、Ctrl+Space（Raycast）を素早く押すと a と空白になる |
| A の Ctrl だけ `hold-preferred` にする | 素早い Ctrl+Space は確実になる。しかし打ち始めに A と次のキーが重なると Ctrl+S などに化けるおそれがあり、そこまでする必要はないと判断した |
| `retro-tap` を付ける | 長押ししても何も押さずに離せば文字を出す設定。K では効かない場面があり、原因を切り分けられなかった。挙動をシンプルにするため外した |

## 影響

- レイヤー 2（数字・記号）やレイヤー 7 を使うときは、手を止めてから S・K を 0.3 秒押し続ける必要がある。
- S・K を長めに押して、何も押さずに離すと何も出ない。

## 今後見直すきっかけ

| 症状 | 対応 |
| --- | --- |
| レイヤーに入るのが遅く感じる | `tapping-term-ms` を 250ms に縮める |
| A が Ctrl に化ける（`aka` などで Ctrl+K） | `&mt` に `require-prior-idle-ms = <150>` を足す |
| 素早い Ctrl+Space がまた気になる | A だけ `hold-preferred` の案を再検討する |

## 補足

- DYA Studio で変えたキー配置は右手の本体に保存され、このファイルより優先される。反映されないときは DYA Studio の設定タブ →「すべての設定をリセット」を実行する。
- 長押しの判定は右手（central）で行うため、この設定を変えたときは右手の `mona2_r-pmw3610.uf2` だけ書き込めばよい。
